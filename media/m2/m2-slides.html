A wafer's path through the fab

Each process tool works on lots of wafers and writes records about every run. Metrology tools measure some wafers between steps. The furnace in this course grows the oxide; an ellipsometer then measures its thickness on monitor wafers.

How tools talk to the fab

SECS/GEM

SECS-II (SEMI E5) defines the messages; GEM (E30) defines how a tool behaves toward the host: states, events, alarms, recipes, data collection. HSMS (E37) carries the messages over TCP/IP. GEM300 adds carriers, process jobs and wafer tracking (E87, E40, E90, E94).

Interface A (EDA)

SEMI's Equipment Data Acquisition standards (E120, E125, E132, E134, E164): web services with SOAP/XML over HTTP or HTTPS, for collecting detailed equipment data. It does not control the tool and runs alongside SECS/GEM.

OPC UA

IEC 62541, a platform-independent standard for industrial data exchange used across manufacturing. It has security built in: messages can be signed, or signed and encrypted, with certificates and user authentication.

Sources: SEMI Standards Watch, “Intro to SEMI communication standards” (2022); Cimetrix, SEMI EDA / Interface A overview; OPC Foundation. The standards are described here, not reproduced.

How much data is one run?

An example tool logs 40 signals, 1 reading per second each, for a 130-minute run. A fab runs this recipe 6 times a day on 10 such tools.

Predict: how many values per run, and per day for those tools?

Per run: 40 × 1 × 130 × 60 = 312,000 values. Per day: 312,000 × 6 × 10 = 18,720,000 values, for one recipe on ten tools. These are example numbers, not a statement about a real tool; real tools differ widely. That volume is why FDC systems keep summary indicators per step, such as the mean or the slope.

Sampling, clocks and summaries

  • The trace counts seconds from the start of the hold; the MES writes clock times. Clock time = hold_start + time_s.
  • Two systems' clocks can disagree: align them before joining by time.
  • A missed reading is NaN, not 0: the mean skips it.
  • The twin uses one number per run: the hold mean, 999.66 °C here.

Left join or inner join?

An inner join keeps only rows that match in both tables; a left join keeps every run and fills NaN where there is no result.

Predict: with an inner join, how many rows does the table of 24 runs have, and what does the fab lose?

23 rows: run R2026-17 disappears without a message. The correlation over on-time runs does not change, but the table no longer shows that a result is missing, and nobody follows up the missing measurement. A left join keeps the run with NaN thickness: unknown, not zero.

SECOM: real records from a fab

  • 1,567 production records, 590 anonymized signals, a pass or fail line test; 104 fails.
  • 4.9% of the training values are missing; only 148 signals have none.
  • Screening on the training records keeps 440: 24 dropped for more than half missing, 126 as near-constant.

The accuracy trap

always predict pass: accuracy = 1463 / 1567 = 0.934
  • It finds none of the 104 fails, the records the fab cares about.
  • Report numbers that look at each class: the share of fails found, the balanced accuracy (mean of the two classes' shares called correctly, 0.5 here), the AUC (0.5 is chance).
  • Compare every model with this baseline. A model that does not beat it is a valid finding.

Split first, and keep time order

  • Training: the earliest 1097 records (78 fails). Test: the latest 470 (26 fails).
  • The fab changed: 22% fails in July, 3% in September.
  • Everything that learns from data (filling in, scaling, choosing signals, fitting) uses the training records only.

Random features, picked with all the data

scikit-learn's guide to common pitfalls makes 200 samples with 10,000 random features and random labels. It keeps the 25 features most related to the labels, using all 200 samples, then splits into training and test sets.

Predict: the test accuracy, when chance is 0.5?

About 0.76 in the guide, from nothing: the selection saw the test samples. Selecting inside the training set, or inside a pipeline, gives about 0.5, as it should. Put every step that learns from data in a Pipeline, so that cross-validation repeats it inside every fold.

Associated is not shown to be a cause

s059 ranks first in the training records (S2N 0.363), and almost nothing in the test records (0.036).

It falls month by month, and so does the share of fails: something that changed over time moved both.

Integrity and security of connected tools

NIST IR 8356 (2025)

Risks: many low-cost sensors that may give untrustworthy data or have vulnerabilities; all data about an object in one place; displays that can be manipulated; remote control while the display hides the change. Measures include hashes and error detection to verify data, encryption, access governance and a zero-trust approach.

In the fab

SEMI E187 (2022) sets a minimum cybersecurity baseline for fab equipment: operating system support, network security, endpoint protection, security monitoring. E188 covers malware-free equipment integration. SEMI cites a 2018 ransomware incident that paused a major foundry's production.

Data ownership: equipment data are produced on a supplier's tool inside a fab. Who may read and use them is set by contracts and access policies, not by the data themselves.

Summary

  • A fab's records come from separate systems: traces, metrology, MES history. A twin must join them by run and wafer IDs.
  • Keep every run with a left join; mark results as on time, late or missing.
  • Split by time first; screen, rank and fit on the training records only, ideally inside a pipeline.
  • With rare fails, accuracy misleads: report results for each class and compare with a baseline.
  • A screened association is a lead, not a cause. Every connection is also a security risk.
