What virtual metrology is

Virtual metrology predicts a wafer's measurement from the tool's sensor data and from the actual measurements of sampled wafers (Kang et al., 2009). The sampled metrology never stops: it is how the model is trained, checked and corrected.

Thickness and its main driver

  • Most of the spread comes from the oxidation time: about half a nanometre per minute.
  • At one oxidation time, the wafers still spread over a nanometre or two: temperature, moisture and position.
  • No single feature explains everything: the twin needs a model.
  • Wafers of one run share their run's conditions.

A linear model with five features

thickness ≈ 14.79 + 0.5192·t + 0.4731·(T_center − 1000) + 0.2238·H₂O + 0.0145·O₂ + 0.0029·slot
  • Least squares on the 200 training wafers. Units: nm per minute, per °C, per ppm, per slm, per slot.
  • One more minute: +0.52 nm. One degree hotter: +0.47 nm. One ppm more moisture: +0.22 nm.
  • The oxygen flow barely matters: in the simulator it has no effect at all.
  • The intercept is the thickness the model gives at zero for every feature: here only a reference point, far outside the data.

The three zones move together (correlation 0.95 to 0.96), so least squares can split their shared effect into a negative and a large positive coefficient. The penalty pulls them toward each other. Because it compares coefficients, the features must be scaled first: StandardScaler, then Ridge, in one pipeline.

Training, tuning and test data

  • Training runs fit the model. Tuning choices, such as α, use cross-validation inside the training runs.
  • The test runs come later in time and are used once, at the end. Their score is the estimate of how the model will do.
Module 4 · Virtual metrology for oxide thickness11

Cross-validation, done properly

  • Split the training runs into five folds; fit on four, validate on the fifth; rotate; average the five errors.
  • Everything learned from data goes inside the fold: the scaler too. A pipeline makes that automatic: cross_val_score refits the whole pipeline on each training fold.
  • Keep whole runs together. Each fold here is a block of 8 consecutive runs, so no run is split and neighbouring runs stay together.
  • These folds stop leakage within runs, but they are not walk-forward: one fold trains on runs 9 to 40 and validates on runs 1 to 8. For a drifting tool, tune with expanding-window splits over whole runs.
  • Choose the α with the smallest cross-validated error, then refit on all training runs.

scikit-learn: Pipeline, StandardScaler, Ridge, GroupKFold, cross_val_score, GridSearchCV.

Why the folds hold whole runs

  • A flexible model (all products of the features up to degree 3) with almost no penalty.
  • Random wafer folds: 0.50 nm. It has seen four wafers of each validation run, so it can look up the fifth.
  • Run-block folds: 1.46 nm; the test runs agree: 1.17 nm.
  • The lesson: random folds promise about 0.50 nm for a model whose error on new runs is 1.17 nm.

First, a baseline

  • Baseline: the mean thickness of all wafers measured in the 3 runs before this one.
  • It uses only finished, measured runs: never the run itself.
  • Test RMSE: 4.31 nm. It follows slow changes, but not each run's own oxidation time.
  • A model that cannot beat it is not worth running; one that ties it is a valid finding.
Module 4 · Virtual metrology for oxide thickness14

Physics plus a learned correction

  • Textbook Deal-Grove at each run's center-zone reading and time: right shape, wrong level. Every wafer is thicker, by 7.8 nm on average.
  • The error is smooth and systematic: the thin-oxide regime, moisture, this furnace's constants.
  • Hybrid = physics prediction + ridge model of (measured − physics).
  • The correction is learned and cross-validated like any other model.

Test runs and a new recipe

Inside the training range the data-driven and hybrid models tie (0.56 and 0.56 nm), close to the noise no trace explains. On the 140-minute recipe the hybrid's error grows to 0.96 nm, the data-driven model's to 2.33 nm.

Module 4 · Virtual metrology for oxide thickness16

Why the new recipe separates them

  • The data-driven model extends a straight line in time beyond 100 minutes.
  • Oxide growth slows as the oxide thickens, so the line overshoots, every wafer in the same direction.
  • The hybrid takes the time dependence from Deal-Grove, which holds at 140 minutes; only its small correction is extrapolated.
  • All 30 wafers of the new recipe fall outside the range check.

Compute an RMSE

A model's errors (measured minus predicted) on four wafers are +0.4, -0.8, +0.2, +0.6 nm.

Predict: the RMSE.

RMSE = √((0.4² + -0.8² + 0.2² + 0.6²) / 4) = √(0.300) = 0.548 nm. Squaring makes the largest error count most, which is why RMSE is quoted with the largest error alongside it.

When not to trust a prediction

  • Range check: flag a wafer if any feature is outside its training range, widened by 10 % of the range at each end. For oxidation time here: 78 to 102 minutes.
  • A flag is a request to measure, not proof of an error. Industry systems refine the idea: Cheng and co-workers' automatic virtual metrology adds a similarity index (distance of a wafer's process data from the training data) and a reliance index for each prediction.
  • A range check misses problems that keep every feature in range, such as a slowly drifting thermocouple: Module 5.
  • Claim only what the data support: on simulated data, a good score shows the models recover the course's simulator, not a real furnace.

Summary

  • Virtual metrology predicts every wafer from trace data; sampled metrology keeps training, checking and correcting it.
  • Ridge regression in a pipeline: scale, then penalize; tune α with cross-validation inside the training runs.
  • Keep whole runs together and test in time order, or the scores will flatter the model.
  • Beat a simple baseline first. A hybrid of physics and a learned correction ties the data-driven model inside the range and holds up better outside it.
  • Flag wafers outside the training range and send them to metrology.
